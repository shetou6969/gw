# GW Panel 0.5.0

Web 集中管理版。安装时选择“主控”、“节点”或“主控兼节点”，协议、出口、服务操作和删除清理均通过 Web 完成。不再安装交互式节点菜单或终端二维码工具。

此版本沿用 0.2 的集中管理架构，增加管理程序版本、GitHub Release 更新和 Web 2FA。已完成本地 HTTPS、核心流量和控制流程测试；尚未在真实 Debian/Ubuntu 服务器进行安装验收，请先在测试服务器验证。

## 快速安装与维护

主控与节点使用同一个安装入口：

```bash
curl -fsSLo gw-bootstrap.sh https://raw.githubusercontent.com/shetou6969/gw/main/bootstrap.sh && sudo bash gw-bootstrap.sh
```

安装时选择“主控”、“节点”或“主控兼节点”。引导程序从 GitHub Release 下载 `gw-panel.tar.gz` 和 `SHA256SUMS`，验证版本、SHA256 及包内仓库标记后执行安装。发布新版本后，在已安装的任一服务器运行 `sudo gw-panel --update`；修改管理员密码、Web 地址或节点主控地址运行 `sudo gw-panel --configure`；查看本机管理程序版本运行 `gw-panel --version`。升级会备份主控数据库和节点凭据，检查已安装的服务，失败时恢复旧程序与状态。

### 主控和节点安装在同一台服务器

新服务器在安装菜单选“3 主控兼节点”。安装器先启动主控，再提示在 Web“服务器 → 添加服务器”登记本机节点：公网 IP 填这台服务器的对外地址；**接入验证来源 IP 填 `127.0.0.1`**；内部转发端口按需设置。复制一次性接入码回到安装器，节点会通过本机回环地址连接主控并验证证书指纹。主控 Web 端口、节点接入端口、代理协议监听端口及内部转发端口不得冲突。

已有主控先运行 `sudo gw-panel --update` 升至 0.4.0，再在 Web 登记本机节点并运行 `sudo gw-panel --add-node`。如果节点安装中断，主控仍可使用；重新运行 `sudo gw-panel --add-node` 继续。删除这个本机节点只移除 Agent 和代理配置，主控、管理员账号及 Web 服务保留。

本机节点对其他节点做加密中转时，来源地址按登记的公网 IP 约束；若服务器实际经 NAT 使用不同的出口 IP，需要确认或调整网络来源后再使用跨节点出口。

服务器列表以“配置已同步 / 配置待应用”显示节点状态。目标与已应用版本号是配置修订号，每次新增、修改或删除协议时递增，不代表协议数量；鼠标悬停在状态上可查看具体版本号。

也可从完整的本地发行包执行 `sudo bash install.sh --update`，无需远程下载。每次发布先提升 `VERSION`，推送到 `main` 后仓库工作流运行测试并创建对应的 `vX.Y.Z` 正式 Release。相同版本的后续提交不会覆盖已发布的安装包。

## 一、使用流程

### 1. 安装主控

上传并解压完整源码包，在目录内执行唯一安装入口：

```bash
sudo bash install.sh
```

选择“1 安装主控”（同机安装则选“3 主控兼节点”），填写：

- 主控公网 IP 或域名。
- Web HTTPS 端口，默认 `8443`。
- 节点上线 HTTPS 端口，默认 `9443`，与 Web 分开。
- 管理员账号、密码（至少 12 位）。
- 已有证书路径，或自动生成自签证书。

在云安全组/系统防火墙放行选定的两个主控端口，打开安装器输出的 Web 地址。自签证书需要在浏览器正确安装信任；公开可信证书也可在安装时提供。节点使用面板接入码内的 SHA256 证书指纹验证主控，不发送凭据给未匹配的证书。

主控程序与 SQLite 数据库在同一台机器。默认仅一个管理员账号，可在 Web 修改密码、启用 TOTP 两步验证并生成一次性恢复码。登录有速率限制，密码以加盐 PBKDF2 存储。会话保存在页面内存，8 小时过期，刷新页面需重新登录。

### 2. 先在 Web 登记节点

在“服务器 → 添加服务器”填写：

- 名称。
- 节点公网 IP（IPv4 或 IPv6）。
- 可选“接入验证来源 IP”，默认等于公网 IP；NAT 出站地址不同时填写实际连接主控所使用的地址。
- 内部加密转发端口范围，默认 `20000–29999`。

面板生成节点 ID、一次性密钥和主控证书指纹，组合为一个接入码，有效期 30 分钟。完整接入码只在生成时显示；待安装的节点可重新签发。仅登记 IP 不足以接入，必须同时持有接入码。

### 3. 安装节点

在登记过的服务器上传并解压同一包，执行：

```bash
sudo bash install.sh
```

选择“2 安装节点”，填写主控 IP/域名、节点上线端口、面板生成的接入码。

接入顺序：验证主控证书指纹 → 主控验证登记 IP/一次性密钥 → 保存独立节点凭据 → 从 sing-box 官方安装核心 → 启动 Agent 与代理服务。未登记、IP 不匹配、接入码过期或不正确时，安装在核心/服务安装之前停止。若系统缺少 Python，安装器可先安装通信所需基础依赖。

接入成功后 Agent 每 10 秒主动联系主控。无需在节点公开额外管理 API 端口。初次认证成功但安装中断时，重新执行同一安装命令可继续；认证响应丢失时保留本机待确认凭据，用相同凭据重试，而不是生成第二份身份。

正常安装完成后无需继续输入节点创建命令。源码包中的 `gw.py` 仅作为服务入口，不提供原脚本交互菜单。

### 4. Web 创建协议

节点上线后，“服务器”显示主机名、系统、架构、CPU、内存、磁盘、系统累计网络流量、运行时间、核心版本及服务状态。

在“协议与出口 → 添加协议”选择：

- 协议所在节点、名称、监听端口。
- 协议类型及必要参数。
- 出口：本机 / 其他已接入节点 / 外部 SOCKS5。

UUID、密码、REALITY 密钥等可以自动生成；编辑时默认保留。支持 22 个协议/传输入口：VLESS REALITY、VLESS HTTP2 REALITY、TUIC、Trojan、Hysteria2、AnyTLS、Shadowsocks、Socks、Direct、VMess TCP/HTTP/QUIC/WS，以及 VMess/VLESS/Trojan 的 WS/H2/HTTPUpgrade TLS。

证书方式：自动自签、自动域名证书（sing-box ACME）、已有 PEM 证书。自签模式导出的客户端 JSON 包含需要信任的证书，不通过关闭证书验证来实现连接。域名自动证书需要域名正确解析到该节点，并确保 ACME 验证端口公网可达。

可在 Web“连接信息”中复制 VLESS、VMess、Trojan、Shadowsocks 等支持的协议连接链接，并扫描二维码；二维码在主控本机生成，不调用外部二维码服务。也可下载完整 sing-box 客户端 JSON。自签证书模式的通用分享链接无法携带所需的证书信任信息，因此只提供含证书的客户端 JSON；Direct 固定转发不需要代理客户端。不同第三方客户端对链接和协议的支持不同，客户端 JSON 已通过 sing-box 校验。

## 二、自动配置其他节点作为出口

选择 B 作为 A 上某个协议的出口后，主控会自动：

1. 为这条关联生成独立 SS2022 密钥。
2. 从 B 的内部转发范围分配一个未使用端口。
3. 在 B 的 sing-box 中建立加密内部监听，并将该监听流量直连互联网。
4. 在 A 中建立与之匹配的加密出口及入站路由。
5. 等待 B 确认配置已应用，再向 A 下发依赖 B 的配置。

节点安装时已包含 sing-box，无需在 B 再安装另一个第三方转发项目。每条关联有自己的监听、密钥和配置文件，因此删除一个协议不会删除其他协议仍使用的监听。

内部监听限制来源 IP 为 A 登记的接入来源 IP，并且要求正确加密密钥。A→B 的实际源地址须与该地址一致；多出口 NAT、IPv4/IPv6 混合场景需先确认网络源地址。B 的端口范围应在云安全组/防火墙向 A 放行。主控不能代替未接入的云厂商控制台修改安全组。

本机出口、内部节点出口和外部 SOCKS5 出口按协议独立配置。同一台机器可有多个不同出口。中转出口失败不会自动回退本机 direct。自动内部出口在 B 上直接出网，不会误用 B 的其他客户端协议出口。

为保证配置依赖顺序，当前禁止形成节点依赖环。外部 SOCKS5 是否支持 UDP 取决于对应 SOCKS5 服务；SOCKS5 本身不加密，跨公网可使用上述自动加密节点出口。

## 三、删除和清理

### 删除协议

Web 删除后重新计算配置：移除入口节点的入站/出口/路由，同时移除目标节点中对应的内部转发监听。所有受影响节点回报目标版本后，任务才标记完成，并删除主控中的该协议配置记录。

离线节点保留待清理任务。在线一端可以先清理，离线另一端恢复连接后继续；不会因为页面移除了协议就把清理假报为成功。

### 删除服务器

界面列出并确认连带删除的协议：该服务器上的协议，以及把它选为出口的协议。主控同时为其他相关服务器下发移除配置。

被删除服务器收到指令后：

- 停止并禁用 GW 代理服务。
- 删除 GW 管理的节点配置、缓存和事务备份。
- 移除 GW 代理 systemd 单元。
- 若曾通过面板启用 BBR，在值仍为 GW 设置值时恢复所记录的旧值，并清理 GW 的持久化配置。
- 向主控发送清理回执。
- 收到主控确认后移除本机 Agent 凭据、Agent 服务及安装状态，正常退出。

本地 `/opt/gw` 中的程序代码及已下载核心可保留供再次接入，不包含代理配置/接入密钥。这是“移除管理和配置”，不是清空服务器或卸载操作系统基础软件。不会清理其他程序的 sing-box、Caddy、SSH 或云防火墙规则。

无法连接的机器不能被远程即时擦除，面板会保持等待清理。不要在未清理前复制节点目录给其他人。未实际接入的预登记记录无需远端动作。

## 四、其他 Web 管理功能

- 协议编辑、监听端口/名称/UUID/密码/证书/出口变更。
- 目标与已应用版本、操作任务和审计。
- 节点服务启动、停止、重启。
- 获取最近代理日志。
- 配置 DNS 和日志等级。
- 启用 BBR（内核不支持时返回失败）。
- 指定稳定版本升级 sing-box；官方发布下载并校验 SHA256，升级前验证当前配置，启动失败恢复旧核心。
- 管理员密码修改、TOTP 两步验证及会话退出。
- 面板显示主控版本及各节点 Agent 版本。

旧版的任意配置导入、原脚本命令兼容和 BBR 之外的系统管理没有混入新版 Web 工作流；0.2 面向这次明确的集中管理架构，不是直接在 0.1 的 shell 菜单外套网页。

## 五、部署与目录

安装器目标：Debian 11+/Ubuntu 22.04+、systemd、amd64/arm64。代码在本地 macOS 测试，不代表已完成 Linux 安装验收。

- `/opt/gw`：本地程序包和官方 sing-box 核心。
- `/etc/gw`：主控数据库、账号、证书，或节点接入凭据。
- `/var/lib/gw-node`：仅节点端，GW 拥有的代理配置及运行数据。
- `gw-controller.service`：主控。
- `gw-agent.service`：节点主动同步。
- `gw-proxy.service`：节点代理。

同一服务器已有其他代理时，本项目使用独立服务名/配置目录，不会自动接管原 233boy 节点；仍需要避免端口冲突。遇到未带所有权标记的既有节点目录，会拒绝覆盖。

与 0.1 不兼容，不能直接把其数据库覆盖为新版。当前安装器拒绝自动覆盖 0.1 的 `/opt/gw`；生产迁移应另行规划。

依赖只包括既有操作系统软件源中的基础包，以及 `SagerNet/sing-box` 官方发行包。Python 仅标准库；Web 无外部 CDN/npm/二维码服务；无 233boy 或其他代理面板仓库运行依赖。默认 sing-box 固定为 `1.14.4`。校验和匹配官方元数据不等于对官方核心进行了代码安全审计。

公开仓库：`shetou6969/gw`。本地包的 `sudo bash install.sh` 也可独立使用。

## 六、配置一致性与维护边界

协议和节点变更在主控数据库事务中生成整台节点的期望配置；核心配置在下发前以及节点应用前校验。Agent 替换文件后重启，失败恢复原配置；成功删除的配置不保留在上一版事务备份中。启动时发现未完成事务会恢复并重启旧配置。磁盘损坏、断电及机器被完全控制不在本地测试保证内。

主控数据包含节点代理凭据，请使用 SQLite 备份接口进行离线/一致性备份，并保护备份访问权限。节点下发 API 只能取得该节点配置，不能执行任意 shell。

自签证书默认有效期一年。接入码固定主控证书指纹；更换证书会使旧节点拒绝连接，不能直接更换证书后期待节点自动接受。此版本没有完成不中断的证书轮换工作流，需要在部署前安排证书生命周期。

主控和节点管理程序使用 `sudo gw-panel --update` 从指定 GitHub Release 升级，或使用本地发行包 `sudo bash install.sh --update`。更新不会自动改变代理核心版本；核心升级仍从 Web 面板单独操作。商业计费/多租户、云厂商安全组集成或自动接管旧代理尚未实现。

## 七、测试

```bash
python3 -m unittest discover -s tests -v
python3 tests/integration.py /path/to/official/sing-box
```

真实流量测试需要支持 TLS 1.3 的 Python/OpenSSL 和 curl。它启动临时 HTTPS 主控、模拟两台已登记服务器、真实 sing-box 进程和本地 HTTP 目标，不修改 systemd 或实际服务器。

详细覆盖和未验证项见 `TESTING.md`。
